## Codebase Patterns

- **`verify.sh` local baseline is `3 passed, 1 skipped, 0 failed`.** The skip is
  `Gradle build — no JDK on PATH`. Per CLAUDE.md §3 that is NOT green: every Kotlin claim
  in a change rests entirely on CI. Say "3 passed, 1 skipped" in notes, never "green",
  unless the change touched no Kotlin (then say so explicitly).
- **Four cheap CI gates run locally with no toolchain** and are worth running on any change:
  `Tests/Conformance/check-single-fixture.sh`, `.chief/tests/verify-skip-policy.sh`,
  `npm --prefix packages/react-native run check:control-surface`,
  `Tests/Conformance/drift-control.sh --port swift`. The kotlin drift control needs a JDK.
- **Every new doc must be indexed in `docs/README.md`** ("unlinked is unreachable") and carry a
  `> **Status:** … · **Updated:** … · **Owner:** …` line. Bump the index's own Updated date too.
- **Reference-counting recipe used all through 900**, reusable for any symbol sweep:
  `grep -rhoE '(struct|class|enum|protocol|actor) [A-Z][A-Za-z0-9_]*' ios/Sources | awk '{print $2}' | sort -u`
  then per name `grep -rn --include='*.swift' -w <name> ios/ | grep -v '<decl form>' | wc -l`.
  Kotlin equivalent over `android/src`. Refcount 0 or 1 is the shortlist, not the answer.
- **A zero refcount is NOT reachability, and in this repo it is usually not even evidence.**
  Six ways they come apart, all present: external consumers (the entire public API of both ports
  reports zero — `AmphoraUploader` is referenced nowhere outside its own file), Room/kapt codegen,
  framework dispatch, reflection *inside libraries* this tree merely feeds, **symbols bound by
  string** (`BlockReason.powerLow`: zero refs in both ports, live via `vectors.json`), and **edges
  that only exist across a process boundary** (`taskDescription`, the reconciler adopt path). Before
  believing a zero, grep the *fixture* and the *docs* for the value's spelling, not just its symbol.
  Full register: `docs/reference/dead-code-undecidable.md`.
- **Verify a proposed deletion by performing it, then reverting.** Comment the symbol out, run
  `swift build` and `swift run --package-path ios AmphoraPathTests`, restore, confirm `git status`
  is clean. Costs ~10s and converts a prediction into an observation — which is what this repo's
  docs require anyway. Note a clean *build* proves nothing here; the suite is where it dies.
- **GitHub anchor slugs drop `—` in place, without inserting a space:** `foo — bar` → `foo--bar`.
  A link checker that substitutes a space instead reports every cross-doc link in `docs/reference/`
  as broken. Test any such checker against a link known to work before trusting its output.

LEARNINGS FOR FUTURE ITERATIONS.
- **The tree is disciplined; do not expect a big harvest.** Zero commented-out code blocks in
  any source language, zero unused Swift imports, one TODO — and that TODO names future work
  rather than hiding an abandoned path. The findings are small and specific by nature.
- **A zero refcount answers a different question than "is this dead".** Three of the four
  blind spots in §4 actually occur here (kapt codegen, framework dispatch, external

  `urlSession(...)`, `onAvailable`/`onLost`/`onCapabilitiesChanged`, `onResponse`/`onFailure`,

- **Cross-port asymmetry is the strongest dead signal available in this repo**, and it cuts
  both ways. `inState` is Kotlin-only and uncalled → stray. `renewLease`/`pruneCompleted` are
  uncalled in *both* ports → a specified surface, not an accident. And Swift's
  `stageIfRequired` is uncalled while its Kotlin twin IS called → the **caller** is missing,
  which is port drift, not dead code.
- **A REAL BUG FOUND, out of scope here, worth a tasklist.** `DefaultUploadEngine.swift:178-253`
  never calls `sources.stageIfRequired(job)`, so a `ph://` job hands
  `URL(fileURLWithPath: "ph://...")` straight to the background session. Kotlin does call its
  twin at `DefaultUploadEngine.kt:217`. The iOS Photos-asset path is broken.
- **A second live gap.** `nativeResumeUnavailable` (`DefaultUploadEngine.swift:28`) is never

  degradation to non-resumable upload that the doc calls "a metric worth alerting on".
- **FOR THE 901 DOCS TASKLIST:** `docs/guides/tusd-integration.md` exists and is **not indexed
  in `docs/README.md`**, whose own rule is "unlinked is unreachable". Left alone deliberately —

LEARNINGS FOR FUTURE ITERATIONS.

- **The headline, and it recontextualises the whole tasklist:** applied honestly to the top of this
  library, S1/S3 report **the entire public API of both ports as dead**. `grep -rn AmphoraUploader
  ios/` returns two lines, both inside the file that declares it. `configure` and
  `handleBackgroundEvents` — the two call sites `ios-host-integration.md` labels *"Not optional"* —
  return one line each, their own declaration. The searches that produced the inventory, pointed at
  the one type this library exists to expose, would delete the library. **Any future refcount sweep
  here must state that up front**, or it is measuring how much of the tree is a library rather than
  how much is dead.

- **NEW CLASS, and it caught a real near-miss: symbols bound by string, not by reference.**
  `BlockReason.powerLow` has **zero** references in **both** ports — by US-1's own reasoning
  (cross-port symmetry, the signal that condemned `WireDialect.Rufh`) the strongest dead signal this
  repo offers. It is live. One of the 40 vectors, `row-14-power-low`, reaches it by raw-value decode.
  **I verified this by running the deletion, not by reasoning about it:** `swift build` →
  `Build complete!` (compiles clean, nothing references it), then `swift run AmphoraPathTests` →
  `ConformanceTests.swift:165: Fatal error: Unexpectedly found nil`. Restored; 46 passed. Do this.
  The whole tasklist's most expensive lesson is that a quoted search reads exactly like an executed
  one, and the same is true of a predicted build result.

- **NEW CLASS: edges that exist only across a process boundary.** `taskDescription` is written before
  termination and read after an OS-initiated relaunch; the `Reconciler` adopt path is reachable on no
  other launch; `systemCompletionHandler` has an undecidable symbol at *both* ends. Invisible to grep
  **and** to the local suite. This is the sharpest omission from §4 because it is the scenario the
  library exists for, and it maps exactly onto ROADMAP's 40 unverified device cells. **Never let a
  hygiene sweep delete a path the project already documents as unexercisable.**

- **A LIVE DEFECT, found by reading a row instead of counting it — reported, not fixed.**
  `UploadWorker.kt:84` tags work `"amphora-job:$jobId"` and its two `addTag` calls (`:92`, `:114`) are
  the only ones in the module. `Reconciler.kt:111` queries `getWorkInfosByTag("amphora-job")` — the
  bare prefix, no colon, no id. **`getWorkInfosByTag` matches by string equality; WorkManager has no
  prefix query.** So `liveWorkJobIds()` returns an empty set on every launch and **the Android adopt
  path can never fire** — every live upload looks orphaned and takes the recover path. Corroboration
  that the two ends were written against different assumptions: `:113` strips `"amphora-job:"` off
  results the query cannot have returned. No test covers it. Unverified locally (no JDK, and it needs
  an instrumented device regardless). Swift is unaffected — it matches on `taskDescription` via
  `session.allTasks`. **Third defect this tasklist surfaced without fixing.**

- **The inventory's "no reflection anywhere in the tree" was true and misleading**, and that shape
  recurs. There is no `Class.forName` here because the reflection that reaches this code lives in
  Room (`UploadDatabase::class.java` → `UploadDatabase_Impl` by name), WorkManager (the worker class
  name, persisted into a row) and `TurboModuleRegistry.getEnforcing('Amphora')`. Searching *this*
  tree for reflection can only ever return zero. **A search whose scope excludes the mechanism cannot
  find the mechanism, and reports a confident zero instead of an error.**

- **Mechanical: my own anchor-checker was wrong twice before it was right.** GitHub's slugger *drops*
  `—` in place without inserting a space, so `foo — bar` → `foo--bar`. Two normalisers that inserted a
  space reported 16 broken cross-doc links that were all fine. Verify the verifier against a link you
  know works before believing it.
