**Files changed.** `gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.{jar,properties}` (new,

### What the compiler found — five defects, in the order it found them

1. **`androidx.room:room-ktx` missing.** kapt rejected *every* `suspend`/`Flow` DAO query:
   "To use Coroutine features, you must add `ktx` artifact from Room". Run 33038526156.
2. **`Call.await()` had never been written.** `TusTransport` called it at four sites. Added
   `transport/CallAwait.kt` — an `enqueue`-based `suspendCancellableCoroutine` bridge, so
   cancelling the coroutine cancels the HTTP call instead of leaking the socket.
3. **`UploadWorker` referenced `AmphoraGraph` with no import.**
4. **`ParcelFileDescriptor.seekTo()` does not exist.** `SourceResolver.open` used it to probe
   seekability. Replaced with `Os.lseek(fd, 0, SEEK_SET)`, which is what actually raises
   `ErrnoException(ESPIPE)` on a pipe — the behaviour the surrounding comment already claimed.
   Run 33039150462.
5. **`CoroutineWorker.onStopped()` is final.** WorkManager expresses the stop as *cancellation of
   `doWork`'s coroutine*, so the override could never have existed. The offset flush and lease
   release moved into a `withContext(NonCancellable)` `finally` — `NonCancellable` is load-bearing
   there, since the job is already cancelled when Android 15 pulls the FGS budget.
   Run 33039150462.

### Toolchain and wrapper

Gradle **8.10.2** pinned (AGP 8.6.1 needs ≥ 8.7; Kotlin 2.0.21). Both the distribution
(`31c55713…4c26`) and the wrapper jar (`2db75c40…8046`) are checksum-pinned and match
`services.gradle.org`'s published values. CI now runs `gradle/actions/wrapper-validation@v4`
(**success**) so the committed binary is checked against Gradle's known-good list, and invokes
`./gradlew` rather than the runner image's ambient gradle — which was 9.7.0 and could change under
us without a commit here.

### Test-harness fixes (the tests could not have run without these)

- `testOptions.unitTests.isReturnDefaultValues = true` — the mockable `android.jar` throws
  `RuntimeException("Stub!")` from every framework method, and `StorageGovernorTest` subclasses a
  real `ContextWrapper`.
- `testImplementation("org.json:json:20240303")` — `org.json` is stubs-only in `android.jar`, and
  `ConformanceVectorsTest` parses the shared vector file with it.
- unit-test `workingDir = rootDir` — both ports read the *same* repo-root-relative
  `Tests/Conformance/vectors.json`; Gradle runs tests from `android/`. Deliberately not a second
  copy of the fixture, and deliberately not a fix to the path itself, which is `110`'s story.
- `kapt` `room.schemaLocation` — `UploadDatabase` sets `exportSchema = true` and was exporting
  nothing.
- `testLogging { events("passed", "skipped", "failed") }` — so a task that runs zero tests cannot
  read as one that runs forty.

### Learnings for future iterations

- **The wrapper alone breaks the local gate.** `.chief/verify.sh` branched on `[ -x ./gradlew ]`;
  committing one made it try to run Gradle on a Mac with no JDK, which would have turned a
  legitimate SKIP into a FAIL. It now probes `java -version` first. US-3 owns making that
  distinction rigorous, but it had to be correct the moment the wrapper landed.
- **CI is the only Kotlin compiler available here.** No JDK, no Android SDK locally, and the SDK is
  far too heavy to install for this. Budget ~3 minutes per Android round trip and batch fixes by
  reading every source file before pushing; that is what kept this to three runs for five defects.
- **`gh run view <id> --job=<jobId> --log`** is the command that gives you per-test lines;
  `--log-failed` gives you nothing once the job is green.
- **Two real defects the compiler cannot see, left unfixed and recorded here** (neither is in any
  story's criteria; both are behavioural):
  - `AmphoraGraph.of(context)` constructs a **brand-new graph on every call** — no caching, unlike
    `AmphoraUploader.get`. Every `UploadWorker` execution therefore builds its own Room database
    and its own governors, which defeats the single-runner lease it relies on.
  - `Reconciler.liveWorkJobIds()` calls `getWorkInfosByTag("amphora-job")`, but `UploadWorker`
    tags work as `"amphora-job:$jobId"`. The tag never matches, so reconciliation adopts nothing
    and will restart work that is already running.

## US-3 — A skipped check can never read as a passing one

`.chief/verify.sh` reported two outcomes and exited 0 when a toolchain was missing, so a run
that compiled nothing was indistinguishable from a run that compiled everything. It now reports
three, and the two environments disagree about skips on purpose.

**Files changed.** `.chief/verify.sh`; `.chief/tests/verify-skip-policy.sh` (new);
`.github/workflows/ci.yml` (new `verify-policy` job); `docs/reference/continuous-integration.md`
(new section "A skipped check is not a passing check"); `docs/README.md`.

### The policy

- `PASS` / `FAIL` / **`SKIPPED`** — and skips are counted separately and **named** in the summary
  (`verify: SKIPPED checks — these did NOT run and are UNVERIFIED:`), because "3 skipped" does not
  tell you that *Android* is the one nobody compiled.
- Any run with a skip in it ends `nothing failed, but N check(s) never ran. This is NOT a full
  pass.` The line `every check ran and passed` is now reachable only by a fully-executed run.
- **Local:** skip is tolerated, exit 0. **Strict (CI):** skip is a `FAIL`, exit 1. Selected by
  `CI=true` (GitHub Actions sets it); `AMPHORA_VERIFY_STRICT=1/0` overrides either way.

### Evidence

Local gate on this branch: `3 passed, 1 skipped, 0 failed`, exit 0 — the skip is `Gradle build —
no JDK on PATH`, named in the roster.

`.chief/tests/verify-skip-policy.sh` runs the *real* verify.sh with an **emptied PATH** — the
"Android toolchain removed" counterfactual, plus the other two for free, at zero build cost
because nothing can run — and asserts case 1 (local: SKIPPED, never PASS, exit 0, all four skips
named, no "every check ran and passed"), case 2 (`CI=true`: FAIL, non-zero, no bare SKIPPED line),
case 3 (the override works in both directions).

**Run 33039907367** (push, head `cce0732`), job `verify-policy` **success** —
`| SKIPPED Gradle build: no JDK on PATH` / `| verify: 0 passed, 4 skipped, 0 failed` /
`| This is NOT a full pass.` then `| FAIL Gradle build: SKIPPED (no JDK on PATH)` /
`| verify: 0 passed, 4 skipped, 4 failed`, ending
`verify-skip-policy: all assertions passed`. Jobs: `verify-policy` success, `android` success,
`react-native` success, `ios` **failure** — still the Sendable error US-1 recorded, which no
story in this tasklist owns.

The test is **not vacuous**: mutating verify.sh's CI detection to `elif false` locally produced
3 failed assertions ("expected a non-zero exit under CI=true, got 0").

### Learnings for future iterations

- **`verify.sh` is still not identical to CI**, and that is now written down in
  `docs/reference/continuous-integration.md` under "Known divergence" rather than left as folklore:
  verify.sh omits `-Xswiftc -warnings-as-errors` (which is why the `ios` red is invisible locally)
  and runs `./gradlew build` where CI runs `:android:assemble` + `:android:testDebugUnitTest`.
  A green verify.sh does not predict a green run — check `gh run list`.
- **The counterfactual is cheap because an empty PATH skips everything.** `env -i PATH=$(mktemp -d)`
  gives a hermetic "no toolchain" machine in milliseconds; no need to uninstall anything or to
  reach for a container.
- **Bash here is 3.2** (macOS `/usr/bin/env bash`). Avoid arrays under `set -u`; the skip roster is
  a newline-accumulated string for exactly that reason.
- **`$?` after `out="$(cmd)"`** is the command's status, which is what makes the two-verdict
  assertions readable. Capturing through a pipe to `tail` loses it — check the exit separately.
- **The `ios` Sendable failure is now the only red job on this branch** and it belongs to no story
  here. Whoever picks it up: `BackgroundSessionManager` is a `public final class: NSObject` with no
  `Sendable` conformance, stored in the `Sendable`-conforming structs `NativeResumableTransport`
  and `TUSKitTransport`.
