## Codebase Patterns

- **Link checking here needs a GitHub-accurate slugifier.** Headings in this tree are full of
  spaced em dashes (`## 1. Where this actually is — 2026-08-27`). GitHub drops the em dash and maps
  *each remaining space to its own hyphen*, producing `...is--2026-08-27`. A slugifier that collapses
  `\s+` to one hyphen reports 25 false positives across these docs. Correct recipe: lowercase, strip
  backticks, unwrap `[text](url)` to `text`, delete everything not `\w`/space/hyphen, then
  `.strip().replace(' ', '-')`. Skip fenced code blocks when collecting headings.
- **The banner regex.** `head -5 "$f" | grep -q '^> \*\*Status:\*\*.*\*\*Updated:\*\*.*\*\*Owner:\*\*'`
  — the banner is always line 3, a blockquote, immediately after the `# Title` and a blank line.
- **`verify.sh` exits 0 on a skip.** Never read exit 0 as green. Read the summary line. On these
  machines the skip is always `Gradle build — no JDK on PATH` and failures are always `0`; the
  passed count is `3` or `4` depending on whether `packages/react-native/node_modules` exists
  (`TypeScript dependency install` is conditional on its absence). Quote the line you saw.

### Learnings for future iterations

- **`verify.sh` prints `3 passed, 1 skipped` here, not `4`.** The Codebase Patterns note above says
  4; that is only true when `packages/react-native/node_modules` is absent, because
  `TypeScript dependency install` is conditional on it. Both are `0 failed`. Read the summary line,
  not a remembered number.
- **The mechanical sweeps found almost nothing; the reading found everything.** Every path, every
  identifier, and every count in the docs already resolved. All 10 defects were *semantic* — a name
  that exists but means something else, a set that is missing a member, a version that is real but
  not the one pinned. A link checker would have reported this tree clean. Do not let a green
  automated sweep stand in for reading a spec against a type declaration.
- **`docs/reference/state-machine.md` is normative and had never been read back against a port.**
  Where a doc claims to be the specification, the drift is worse than ordinary staleness, because a
  reader has no reason to doubt it and the ports agreeing with *each other* hides it completely.
  The fixture is not a check on this doc: it encodes the ports' behaviour, so the doc can be wrong
  while all 40 vectors pass. That is what happened.
- **`## Corrections` sections are now a convention** (CLAUDE.md §6). Nine docs carry one. Each also
  states what its pass did *not* check — US-3 owes the same for the sweep as a whole.
- **US-3's archive question, answered in advance: nothing here warranted archiving.** Every doc read
  in this pass is current and load-bearing; the three dead-code docs look historical but are the
  record of a decision, which this portfolio keeps deliberately. `docs/archive/` still does not
  exist and git cannot commit it empty — US-3 should say that rather than create a placeholder.
- **Two ADR slots are named and unfilled** — `0001-adopt-rufh-build-clients.md` and

**The archive decision was made against evidence, not asserted.** US-2's note predicted "nothing here
warranted archiving"; that prediction was re-derived rather than inherited, because a prediction is

| Question | Command | Answer |

### Learnings for future iterations

- **The banner date is a working defect detector, and it is the cheapest one in this tree.** Two of
  the three defects this story found were in the only two `docs/reference/` files still carrying the
  pre-sweep date. Before reading anything, sort `docs/` by the `Updated:` field and start at the top —
  that is what a doc sweep's triage should be. It also means **re-stamping a file you only skimmed
  destroys the signal**, which is why `ios-host-integration.md` was left at `2026-08-19`.
- **A prior story's forward-looking note is a lead, not a finding.** US-2 wrote "US-3's archive
  question, answered in advance: nothing here warranted archiving" — which was the right answer, and
  was reached without running the two `git log --diff-filter` queries that make it checkable. Inherit
  the lead; re-derive the evidence.
- **"Looks stale" splits three ways here, and the distinction is worth making explicitly in prose:**
  *stale* (correct in place, `## Corrections`), *history* (the record of a decision — keep untouched:
  the dead-code inventory is the **approval** record its removal record cites row by row, not a
  superseded proposal), and *an open obligation* (the 40 `NOT YET VERIFIED` cells are the ledger
  working, not the ledger rotting). Only a fourth category — superseded by a named successor — earns
  `docs/archive/`, and this tree has none.
- **The one-directional blind spot is now written down** (`documentation-record.md` §4). Every sweep
  in this tasklist checked "is each claim in the doc true of the code?" and never "does the code do
  something no doc mentions?". An *omission* would have survived all three stories. If a future
  tasklist wants the other direction, that is a different method and a different cost.
- **`docs/reference/documentation-record.md` is where a future doc sweep starts.** It states the bar
  for archiving, the seven deliberate keeps with reasons, and what this pass did not verify — written
  while nothing was pressing on the judgement, so the next pass is not deciding it under the
  incentive to tidy.
