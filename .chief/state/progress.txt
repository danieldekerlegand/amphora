## Learnings for future iterations

- NO JDK ON THIS MACHINE. `/usr/bin/java` exists but is the macOS stub and exits non-zero;
  `.chief/verify.sh` probes with `java -version` and reports Gradle as SKIPPED. Nothing Kotlin can
  be compiled locally — the android CI job (`./gradlew --no-daemon :android:testDebugUnitTest`) is
  the first thing that ever compiles it. Say so in notes rather than implying Kotlin was verified.
- The Swift "test suite" is an executable target (`AmphoraPathTests`), not XCTest. Assertions are
  `precondition`, which TRAPS. For anything a story calls a "failure that must not crash", throw a
  `LocalizedError` and catch it in `main()` — a trap and a thrown error look very different to
  someone reading CI output.
- `#filePath` is the only compile-time anchor available to the Swift target; there is no bundle
  resource path (`AmphoraPathTests` declares no resources). Walking up from it is the pattern to
  reuse for any other repo-root fixture.
- Run negative controls with ABSOLUTE paths. The Bash tool's working directory persists across
  calls, so a `cd ios` in an earlier call silently made a later `swift run --package-path ios`
  resolve to `ios/ios`.

## Learnings for future iterations

- THE CI SWIFT REJECTS `nonisolated(unsafe)` ON A STRUCT'S STORED PROPERTY ("'nonisolated' is
  redundant … this is an error in Swift 6") while the local toolchain accepts it as a suppression.
  To hold a non-Sendable reference inside a Sendable struct, wrap it in a small
  `struct X: @unchecked Sendable` instead — that compiles identically in both places. Do not
  discover this by pushing: it costs a CI round trip (~4 min).
- The local Swift does NOT warn about a non-Sendable CLASS stored in a Sendable struct, but DOES
  warn about a non-Sendable EXISTENTIAL (`any P`). So converting a concrete stored property to a
  protocol for testability can turn a locally-green build red without changing anything real.
- A CONTENT SENTINEL MUST BE SPECIFIC ENOUGH NOT TO MATCH PROSE. check-single-fixture.sh grepped
  tracked *.json for `row-01-enqueue` and went red on de1b5cb because chief's own prd.json and
  tasks/*.json quote that id when a story's notes describe the check. Matching `"id": "<sentinel>"`
  fixes it and still catches a reformatted copy. Gates that fire on people writing about them get
  ignored.
- THE ANDROID JOB WAS FLAKING INSIDE KAPT, twice in three runs (33041928703 killed
  kaptReleaseKotlin, 33042386253 killed kaptDebugKotlin), with no diagnostic beyond "A failure
  occurred while executing KaptExecutionWorkAction" — and a rerun of the identical commit passed.
  Both kapt tasks run concurrently in-process and the daemon heap was 2g; 4g plus --stacktrace.
  If it recurs, the stacktrace is now in the log. `gh run rerun <id> --failed` is how to tell a
  flake from a real failure.
- Gradle's `--tests 'dev.amphora.ConformanceVectorsTest'` filter works on `testDebugUnitTest`, and
  android/build/test-results/testDebugUnitTest/*.xml carries the assertion message even when the
  console output elides it. Cat the XML when grepping for WHY a Kotlin test failed.
- Swift's FileManager enumerator reports /private/var/… while `temporaryDirectory.path` is /var/…;
  resolve symlinks on BOTH sides before diffing directory inventories or the relative paths in the
  failure message come out mangled.
- The negative-control pattern in this repo is now: mutate → run → require red FOR THE NAMED REASON
  → restore → prove the tree is byte-identical. `.chief/tests/verify-skip-policy.sh` and
  `Tests/Conformance/drift-control.sh` are the two instances; copy their shape rather than writing
  a fresh one.
