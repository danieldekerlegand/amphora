## Codebase Patterns

- **Never trust a script in `integration/` that has no green run recorded against it.**
  `run.sh` and `resume.sh` were both written with `curl -X HEAD`, which makes curl send HEAD and
  then block waiting for a response body that HEAD by definition never sends (`curl: (18) transfer
  closed with N bytes remaining to read`). Use `curl --head`. That this shipped is proof the
  scripts had never once been executed.
- **Pin container images by digest, never by a `RELEASE.*`/version tag.** MinIO prunes old release
  tags off Docker Hub; the 2024-06-13 pins were simply gone. `docker image inspect --format
  '{{index .RepoDigests 0}}'` after a pull gives the digest. Keep the human-readable release in a
  comment on the line above so the pin stays auditable.
- **`mc` is already inside `minio/minio` at `/usr/bin/mc`.** There is no reason to pin `minio/mc`
  separately — it is a second tag that can rot for no benefit.
- **A "fresh client in the same process" is not process death.** Both ports shipped harnesses that
  claimed to simulate relaunch by allocating a second transport object. That shows an object with
  no cached offset; it shares the heap, the descriptors and the address space of the first one.
  Real evidence is `kill(getpid(), SIGKILL)` and a second OS process (Swift), or aborting the
  request body mid-flight so the socket dies with `Content-Length` outstanding (Kotlin). Assert on
  the observed exit status 137 — a signal death and an `exit(1)` must never be confusable.
- **tusd's S3 upload id is `<object-key>+<s3-multipart-upload-id>`.** Only the part before the `+`
  names the object. And `mc`'s alias lives in the container's `~/.mc`, so it must be created in the
  same `sh -c` that reads — the one the `create-bucket` service made is in a different container.
  Both bugs sat in `resume.sh` until it was first actually executed.
- **Size a partial upload above 5 MiB before claiming a resume crossed a durability boundary.**
  That is the S3 multipart minimum part size. Below it tusd is handing back a number it still has
  in memory, which is a weaker claim than it looks.
- **Storage claims get sampled, never read off the source.** Redirect the temp directory into a
  tree you control (`TMPDIR` for a shell driver, `java.io.tmpdir` via `android/build.gradle.kts`
  for the JVM), take a baseline with the source already in place, poll during the transfer, and
  fail on a budget. Observed: 4 KiB (Swift) and 0 KiB (Kotlin) extra for an 8 MiB upload.
- **CI is the only place the Kotlin port can be exercised at all.** No JDK and no Android SDK exist
  on these machines; `ubuntu-latest` has both plus Docker. GitHub's `macos-*` runners have no
  Docker daemon, so the mirror is also true: the Swift real-wire harness can only run locally.
- **The harness exit-code contract is three-valued and load-bearing.** `integration/tusd/lib.sh`:
  0 = ran and passed, 1 = ran and failed, 77 = did not run (no Docker), and
  `AMPHORA_REQUIRE_DOCKER=1` turns 77 into 1. Source it from any new integration script. Never
  record a 77 as a pass — that conflation is the entire reason this tasklist exists.

## US-1 — The rotted pin is repaired and the harness runs again (passes: true)

Observed: `integration/tusd/run.sh` → **exit 0** against a live daemon (Docker server 29.3.1),
printing `tusd v2 + S3 integration: 3 MiB create/head/patch/terminate passed; version mismatch
rejected`. 3 MiB genuinely crossed a socket into tusd v2 backed by MinIO/S3. This is the first
green real-wire run in the repository's history.

Two independent defects stood between the repo and that line:

1. **The rotted pins.** The tasklist description names `minio/mc` — in fact *both* MinIO images
   were withdrawn. `docker manifest inspect` answers `no such manifest` for
   `minio/minio:RELEASE.2024-06-13T19-44-55Z` and `minio/mc:RELEASE.2024-06-13T19-44-55Z` alike.
   Docker Hub still lists 1181 `minio/minio` tags, none older than 2025 — MinIO prunes. Replaced
   with digest pins (`minio/minio@sha256:14cea493…` = RELEASE.2025-09-07T16-13-09Z,
   `tusproject/tusd@sha256:6c5e17dc…` = v2.4.0, which had *not* rotted). Dropped the `minio/mc`
   service image entirely in favour of the minio image, which already ships `mc`.
2. **`curl -X HEAD`.** With the stack finally up, the script still died at exit 18 on the first
   HEAD. See the pattern note above. Six occurrences across the two scripts.

### Learnings for future iterations

- **`resume.sh` is NOT yet known to work and US-2 needs it.** It has only ever been run to the
  skip path here. Two things look wrong on reading and should be verified, not assumed: it does
  `docker compose exec -T minio mc cat local/amphora-uploads/…`, but the `local` alias is set in
  the *create-bucket* container, a different container whose `~/.mc` config does not carry over —
  expect to `mc alias set` inline in the same `sh -c`. Second, it kills a `--limit-rate 64k` PATCH
  after 2s and requires a partial offset `> 0`; whether tusd's S3 backend has durably acknowledged
  a non-zero offset that early is an empirical question (S3 multipart minimum part size is 5 MB
  per `docs/reference/platform-constraints.md`, and the source is only 3 MiB — the partial may
  well read back as 0).
- A full `up`→`down -v` cycle costs ~35–60s. Budget for it; don't assume a fast edit-test loop.
- Docker **is** available on this machine. Any future note claiming otherwise should be
  disbelieved and re-checked.

### Learnings for future iterations

- **`resume.sh` is now green** and the prior iteration's two warnings were both right to raise and
  both wrong about the cause. The `mc alias` worry was correct. The offset worry was not: tusd's S3
  store buffers to a local temp file and reports the *buffered* offset, so a 2-second throttled
  PATCH left offset 196608 on a 3 MiB source, well above zero. The actual bug was the object key —
  see the patterns section.
- **The `ios` CI job is still red and it is not this story's doing.** `NetworkGovernor.swift:23`
  and `TUSKitTransport.swift:27` fail under `-Xswiftc -warnings-as-errors` on the macos-14 runner's
  toolchain; Swift 6.2.3 locally does not emit them at all, so a green local build does not predict
  a green `ios` job. Already recorded as an unowned Known divergence in
  `docs/reference/continuous-integration.md`, and `main` fails identically (run 33038523997).
  **Someone should own it** — it is the last thing standing between this branch and a green CI.
- **`testLogging.showStandardStreams` is off**, so a `println` from a test is invisible in the CI
  log. Write the evidence line to a file (`android/build/reports/tusd-real-wire.txt`) and `cat` it
  in a step — do not depend on whether Gradle's JUnit XML happens to carry suite-level stdout.
- **Strictness is keyed on `AMPHORA_REQUIRE_DOCKER=1`, deliberately not on `CI=true`.** The
  `android` job legitimately runs the whole unit suite with no server up, and a skip there is
  honest. Strictness belongs to the step whose purpose is the evidence.
- This tasklist has no research map (`.chief/state/research/` does not exist and no `# Research`
  section was appended to the prompt). The US-1 notes in this file were the map, and they held up.

### Learnings for future iterations

- **Correct a merged record in place; do not rewrite it.** Flip the flag, keep the note verbatim,
  add a sibling `correction` field. Deleting the note destroys the evidence that the flag was wrong,
  and rewriting the file wholesale (`json.dump` with different escaping) buries a two-line
  correction in a 70-line diff nobody will read. `object_pairs_hook=OrderedDict` + `ensure_ascii=
  False` reproduced this file exactly; check `git diff --stat` before committing a machine-edited
  JSON and expect single digits.
- **`docs/README.md` claims every document is linked from it** ("unlinked is unreachable"). There is
  no gate enforcing it, so a new doc must be added there by hand. A five-line Python sweep over
  `\](path)` in `README.md` + `docs/**/*.md` catches both that and a typo'd relative path; worth
  re-running whenever docs move.
- **The `ios` CI job is still red on `NetworkGovernor.swift:23` and `TUSKitTransport.swift:27`**, as
  it was for US-2, in files no story here touched, and `main` fails identically. It is the last
  thing between this branch and a green CI and nothing owns it. A story that fixes those two
  Swift-concurrency errors is the obvious next piece of work.
- Both remaining criteria of this tasklist were about the *record*, not the code, and they took
  about as long as the code did. That is the correct ratio when the artifact being fixed is a
  claim.
