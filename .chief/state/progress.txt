### Two real failures the first-ever run exposed

2. **ios** — `swift build --package-path ios -Xswiftc -warnings-as-errors` fails with

   'BackgroundSessionManager'` in both `Transport/NativeResumableTransport.swift:16` and

   `.chief/verify.sh` runs `swift build` *without* `-warnings-as-errors` while CI runs it *with*.
   Someone has to close that gap or the branch's CI stays red for a reason no story owns.

### Learnings for future iterations

- The local gate and the CI gate are **not running the same commands**. `verify.sh` omits
  `-Xswiftc -warnings-as-errors` and skips Gradle entirely; CI does neither. A green
  `verify.sh` therefore does not predict a green run — check `gh run list` before believing a
  branch is clean. US-3 is the story that should encode this difference rather than leave it
  implicit.
- Evidence commands that actually settle things here: `gh run list --limit 5`,
  `gh run view <id> --json conclusion,jobs`, `gh run view <id> --log-failed`,
  `gh repo view --json visibility`, `git ls-remote --heads origin`.
- A run's **conclusion** is the claim. "CI is wired" without a run id behind it is the failure
  mode this tasklist was written to end.
