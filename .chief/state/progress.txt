## Codebase Patterns

- **Docs are an evidence ledger, not prose.** `docs/reference/environment-matrix.md` and
  `verification-record.md` set the register the whole repo writes in: state the verdict, name
  where it was read from, and refuse to upgrade an unverified cell to make a table look complete.
  New reference docs should carry the same `> **Status:** … · **Updated:** … · **Owner:** …`
  header line and be linked from `docs/README.md` — that file states "unlinked is unreachable",
  so adding a doc without indexing it is an incomplete change.
- **The verify gate reports THREE outcomes.** `.chief/verify.sh`: PASS / FAIL / SKIPPED. On this
  machine `Gradle build` always SKIPS (no JDK on PATH) and that is not a pass — say so in notes
  rather than writing "green". Swift + TypeScript do run locally. `CI=true` flips SKIPPED to
  FAIL, so anything touching `android/` is genuinely verified only in CI.
- **Swift tests are an `.executableTarget`, not a test target.** `swift test` reports "no tests
  found"; the real command is `swift run --package-path ios AmphoraPathTests` (currently 46
  passed). Do not conclude the suite is empty from `swift test`.
- **Bash tool cwd persists across calls in this environment.** A `cd` in one call leaks into the
  next and makes relative paths resolve outside the worktree. Anchor every call with an absolute
  `W=` path.

## US-1 — The repository grants permission to use it (done)

**What I did.** Added `LICENSE` (MIT, © 2026 Daniel DeKerlegand) and recorded the reasoning and the
audit behind it in a new `docs/reference/licensing.md`.

The choice was not free: `packages/react-native/package.json` had declared `"license": "MIT"` since
the package was created, with no `LICENSE` file behind it — npm would have rendered "MIT" on the
package page while the repository granted nothing. MIT makes the existing declaration true instead
of introducing a new position. Apache-2.0 was considered and rejected in writing: its patent grant
has nothing to cover here because the repo deliberately re-specifies no protocol.

**The audit was actually run, not asserted.** Criterion 2 says "verify that rather than assuming
it", so every licence verdict was read from a source:

- iOS: zero external dependencies (`ios/Package.swift`). `TUSKitTransport` does **not** import
  TUSKit — the name records a role, not a linkage.
- Android runtime deps (androidx.annotation/core-ktx/room-runtime/room-ktx/work-runtime-ktx,
  kotlinx-coroutines-android, okhttp): Apache-2.0, read from `<licenses>` in the POMs on Google
  Maven and Maven Central. **AndroidX POMs are NOT on Maven Central** — fetch them from
  `https://dl.google.com/dl/android/maven2/…` or you get an empty answer and might wrongly
  conclude "no licence declared".
- `junit` 4.13.2 is EPL-1.0 (weak copyleft) and `org.json:json:20240303` is Public Domain — both
  `testImplementation` only, so neither reaches a consumer's classpath. The org.json POM confirmed
  the historical "Good, not Evil" JSON License clause is gone in this version.
- `package-lock.json` records a `license` field for all 499 entries, which makes the JS tree
  auditable offline: 426 MIT, 38 ISC, 12 BSD-3, 11 Apache-2.0, 6 BSD-2, 2 0BSD, 1 CC-BY-4.0
  (`caniuse-lite`, data), 1 `(MIT OR CC0-1.0)`, 1 `(BSD-3-Clause OR GPL-2.0)` (`node-forge`, dual).
  Zero unilateral copyleft. The published package declares no runtime `dependencies` at all.
- **The one real finding: MinIO is AGPL-3.0**, pinned in `integration/tusd/docker-compose.yml`. It
  is an unmodified upstream container run as a separate process, never linked or distributed, so
  §13 is not engaged — but the doc states it explicitly rather than claiming "no copyleft
  anywhere", because a reader who greps will find it.
- `tus-js-client` and TUSKit appear **only in prose** (README, two docs). Neither is a dependency.

**File-level convention** (criterion 3 allows headers *or* a stated convention — took the latter,
deliberately): root `LICENSE` is authoritative; each *distributable manifest* carries the SPDX
identifier, since that is what registries and SBOM scanners read; new source files inherit
silently with no per-file header. Per-file headers on 5,951 lines would drift, and a repo with
headers on 80% of its files is less legible about its licence than one with none. Added
`// SPDX-License-Identifier: MIT` to `ios/Package.swift` (after the tools-version line, which must
stay first) and `android/build.gradle.kts`; `package.json` already had the field.

**Files changed.** `LICENSE` (new), `docs/reference/licensing.md` (new), `docs/README.md` (indexed
it, bumped Updated), `README.md` (Licence section), `ios/Package.swift`, `android/build.gradle.kts`.

**Verification.** `.chief/verify.sh`: 3 passed, 1 skipped, 0 failed. Swift build PASS, Swift tests
PASS (46 passed: 4 upload-path, 39 state-machine vectors, 3 I6 transport vectors), TypeScript
typecheck PASS. Gradle build SKIPPED — no JDK on PATH — so the one-line comment added to
`android/build.gradle.kts` is unverified locally and will first run in CI.

### Learnings for future iterations

- **One criterion could not be fully satisfied and the gap is deliberate.** Criterion 3 asks for a
  convention "consistent with how sibling repos in this portfolio express licence posture." The
  agent loop forbids reaching outside the worktree into sibling repos, and this repo contains no
  record of the portfolio standard. The convention was therefore derived from the only in-repo
  evidence — `package.json`'s pre-existing MIT declaration. If the portfolio standard turns out to
  be Apache-2.0 or to require per-file headers, `docs/reference/licensing.md` is the single place
  to change.
- `docs/reference/licensing.md` forward-links to `ROADMAP.md`, which **US-2 must create** for that
  link to resolve. Check it before closing US-2.
- The PRD description is stale in one respect worth knowing before US-3: it says README "still
  asserts *No conformance vectors yet*". It does not — `120` already rewrote the Status section, and
  README now says bytes move and the vectors exist and both ports run them. US-3's real remaining
  target is the `Stubbed:` list (which `60`/`70` closed), plus the new `CLAUDE.md` and
  `CHANGELOG.md`. Read the README before trusting the description's quotes.

## US-2 — A roadmap that states the measured position, not the intended one (done)

**What I did.** Wrote `ROADMAP.md` (337 lines) at the repo root, indexed it in `docs/README.md`
under a new `## Where this is` section, and linked it from `README.md`'s Status section.

**Section 1 is a 14-row evidence table, not prose**, in the register the matrix already uses:
AUTOMATED / MANUAL-ON-DEVICE / NOT YET VERIFIED, every cell naming the run id, command or file the
verdict was read from. The honest summary it lands on: the protocol layer, both state machines and
I6 are measured against a real server; everything *environmental* — the part this library exists
for — is unverified, and the gate that would stop the measured half regressing is itself red.

**Seven phases**, ordered by dependency and carrying no dates (dates would be intentions, and this
repo has already paid once for recording an intention as a result): total gate → binding vectors →
gated real-wire environment → the 40 device cells → storage governor under genuine pressure → RN
TurboModule host adoption → publication. Each states the observation that closes it. Phase 5 fixes
the order explicitly: **reproduce the `TransferUtility` bug FIRST**, because a run showing the new
implementation surviving pressure otherwise proves "the device had enough space", not "the design
retired the bug". Phase 4 is ranked 1–5 by what each row would retire rather than pretending a
40/40 sweep is imminent.

**Non-goals**: no web transfer code, no re-specification of the protocol, no chunk temp files. The
third gets the most space deliberately — it is argued as a commitment, tied to the `Caches`
reclamation failure mode, and closed with the enforcement (3 I6 vectors + `drift-control.sh` driving
`i6-01-fresh-transfer` red on both ports) so a future contributor meets the vectors before the
temptation.
